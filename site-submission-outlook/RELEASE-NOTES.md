Site Submission Outlook 1.2.0 adds separate **Submission state**, **RO state** and **Application state** filters and details columns. Each dropdown starts at **All**, keeps every delivered state individually selectable, and supports multiple selections. Inactive, cancelled, archived and withdrawn records remain visible until deliberately filtered. Blank mapped states appear as **Not recorded**.

Selections apply to the current/next-month plan, historical backlog, totals, details and data-check scope, together with Business unit and site selections. State selections are saved and printed in the screenshot footer. Details retain all recorded states where duplicate source rows disagree. Full source evidence still determines dates and site, so filtering cannot hide date conflicts or an actual submission date. Submissions remain distinct.

**Import `site-submission-outlook-1.2.0.0.pbiviz` over the existing visual, then add the three optional mappings:** Submission state from Submission, RO state from the related Regulatory Objective, and Application state from the related Application. Use each record's own state column. The stable visual identity and four required mappings are unchanged. An unmapped state filter shows a mapping prompt and does not exclude records.

Submitted still requires a valid actual submission date on or before today. A lifecycle state never substitutes for that date. Backlog remains submissions planned before the first displayed month with no actual submission date, separate from the two-month plan. Keep older rows included in report/page/visual filters.
